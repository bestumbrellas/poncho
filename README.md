# Sales CRM

CRM для отдела продаж: лиды из Meta (через Telegram и/или прямой webhook), ROAS по кампаниям,
заказы, которые забираются с почты, возвраты, учёт доход/расход/остаток, интеграция с
Новой Почтой (ТТН + трекинг) и Checkbox (автоматическая отправка фискального чека).

## Стек

Node.js + Express + SQLite (better-sqlite3) — без внешней БД, один файл `data.sqlite`.
Фронтенд — обычный HTML/JS дашборд, без сборки.

## Установка

```bash
npm install
cp .env.example .env
# заполните .env своими данными (см. ниже по каждому блоку)
npm start
```

Откройте http://localhost:3000

## Настройка блоков

### 1. Лиды из Meta через Telegram (текущая схема)

Если лиды уже падают в Telegram-чат/канал (через нативную интеграцию Meta Lead Ads → Telegram,
либо через Zapier/Make/Albato):

1. Создайте бота через @BotFather, получите токен → `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота в тот же чат/канал, куда сейчас падают лиды (боту нужны права читать сообщения).
3. Напишите в чате `/getchatid`, бот ответит ID чата → впишите в `TELEGRAM_LEADS_CHAT_ID`.
4. В `integrations/telegramBot.js` поправьте `parseLeadMessage()` под реальный формат
   сообщений (у каждого сервиса-посредника свой шаблон текста).

### 2. Лиды напрямую от Meta (без Telegram-прослойки, опционально)

Если хотите полностью убрать Telegram и получать лиды напрямую:

1. В Meta App Dashboard → Webhooks подключите `https://ваш-домен/integrations/meta/webhook`,
   подпишитесь на поле `leadgen`.
2. `META_VERIFY_TOKEN` — придумайте любую строку, укажите её и в .env, и при подключении в Meta.
3. `META_APP_SECRET` и `META_PAGE_ACCESS_TOKEN` — из настроек приложения и страницы.

### 3. Заказы с почты (IMAP)

1. Укажите `MAIL_HOST/MAIL_PORT/MAIL_USER/MAIL_PASS` (для Gmail — пароль приложения, не основной).
2. В `integrations/emailParser.js` функция `parseOrderEmail()` — под конкретный шаблон писем
   вашего магазина/маркетплейса нужно доработать регулярные выражения (сумма, номер заказа, ФИО, телефон).
3. Проверка почты идёт по крону (`MAIL_POLL_CRON`, по умолчанию раз в 5 минут),
   либо вручную: `POST /api/email/check-now`.

### 4. Новая Почта

1. Получите API-ключ в личном кабинете Новой Почты → `NOVAPOSHTA_API_KEY`.
2. `NOVAPOSHTA_SENDER_REF`, `NOVAPOSHTA_SENDER_ADDRESS_REF`, `NOVAPOSHTA_SENDER_CONTACT_REF` —
   ref-идентификаторы вашего отправителя/адреса/контакта, их нужно один раз получить через
   методы `Counterparty/getCounterparties` и `ContactPerson/getContactPersons`.
3. Создание ТТН: `POST /api/orders/:id/nova-poshta/ttn` с телом `{ warehouseRef, contactRef, phone, fullName, cod: true/false }`.
4. Обновление статуса доставки: `GET /api/orders/:id/nova-poshta/status`.

### 5. Checkbox (автоматический чек)

1. Получите `CHECKBOX_LICENSE_KEY` и данные кассира (либо `CHECKBOX_CASHIER_PIN`, либо логин/пароль).
2. Как только статус заказа меняется на `paid` или `delivered` — сервер сам:
   открывает смену (если закрыта), формирует чек продажи и отправляет его покупателю
   на email/телефон, указанные в заказе (см. `routes/orders.js` → `PATCH /api/orders/:id/status`).
3. Логика самого чека (название товара, способ оплаты CASH/CARD) — в `integrations/checkbox.js`,
   поправьте под свою номенклатуру.

## Как это работает вместе (сквозной сценарий)

1. Meta Lead Ads → сообщение в Telegram → бот парсит и создаёт запись в `leads`.
2. Менеджер меняет статус лида в дашборде (contacted → qualified → order_created).
3. Клиент оформляет заказ на сайте → письмо с заказом падает на почту → крон импортирует
   его в `orders`, пытаясь автоматически привязать к лиду по телефону.
4. Менеджер подтверждает заказ, создаёт ТТН Новой Почты (`shipped`).
5. При получении оплаты (наложка получена / оплата картой подтверждена) — статус меняют
   на `paid`/`delivered`: автоматически создаётся запись дохода/расхода (себестоимость)
   и отправляется фискальный чек через Checkbox.
6. Если клиент возвращает товар — создаётся запись в `returns`; когда деньги реально
   возвращены (`status = refunded`) — фиксируется расход.
7. Раздел «Дашборд» считает ROAS = доход по заказам кампании / расход на рекламу кампании
   (расход по кампаниям нужно синхронизировать отдельным скриптом с Meta Ads Insights API
   и писать в таблицу `campaign_spend` — заготовка структуры уже есть в схеме БД).

## Структура проекта

```
crm/
  server.js                  — точка входа
  db/
    schema.sql                — схема БД
    index.js                  — подключение SQLite
  routes/                     — REST API (leads, orders, returns, finance)
  services/
    finance.js                 — расчёт доход/расход/остаток, авто-транзакции
    roas.js                     — расчёт ROAS по кампаниям
  integrations/
    telegramBot.js              — приём лидов из Telegram
    metaWebhook.js               — приём лидов напрямую от Meta (опционально)
    emailParser.js                — забор заказов с почты (IMAP)
    novaposhta.js                  — ТТН + трекинг
    checkbox.js                     — авточек
  public/                      — дашборд (HTML/CSS/JS)
```

## Что нужно доработать под ваш конкретный кейс

Регулярки для парсинга Telegram-сообщений и писем с заказами — шаблонные, под самые частые
форматы. Пришлите мне реальный пример сообщения от Meta в Telegram и пример письма о заказе —
подгоню парсеры один в один под них, чтобы данные всегда извлекались корректно.
Ref-идентификаторы Новой Почты и структура номенклатуры для Checkbox тоже индивидуальны
для каждого бизнеса — их нужно один раз получить и вписать.
